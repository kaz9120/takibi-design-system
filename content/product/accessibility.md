見た目で伝えたことは、スクリーンリーダーにも同じ強さで届けます。目標は WCAG 2.2 の AA です。

## 色

- 本文の文字は背景との明るさの比を 4.5:1 以上にする。`text-fg-subtle` は 4.5:1 に届かないので、プレースホルダーと無効の表示だけに使う
- 入力欄の枠など、操作できる要素の輪郭は 3:1 以上にする（`border-line-strong`）
- 色だけで意味を伝えない。エラーは赤い枠に加えて文を出し、状態の色には文字かアイコンを添える

各色の組み合わせのコントラスト比は、作業台（`bun run workbench`）の「基礎 / 色」が、夜と昼のテーマそれぞれで計算して表示しています。

## 名前と状態

- アイコンだけのボタンには `aria-label` で名前を付ける
- 入力欄には見えるラベルを `Field` で結び付ける。プレースホルダーをラベルの代わりにしない
- 処理中は `aria-busy`、エラーは `aria-invalid`、開閉は `aria-expanded` で状態を伝える。Base UI のコンポーネントは自動で付ける
- 完了や失敗の知らせは、`aria-live` の欄で読み上げる（Toast と Button の status は対応済み）

## 押しやすさ

- 指で押す要素は 44px 四方以上の当たり判定を持たせる（`--target-min`）
- 見た目が小さいアイコンのボタンも、当たり判定は広げる

## 動き

- 動きを減らす設定（`prefers-reduced-motion`）では、位置と大きさの動きを消し、色と影の変化だけを残す。CSS は `motion.css` が、Motion を使うコンポーネントは `useReducedMotion` が受け持つ
- 点滅や、5 秒を超えて続く動きを作らない。処理中の呼吸と火の粉だけは例外にする

## 確かめ方

作業台（`bun run workbench`）では、各ストーリーの下のパネルの「Accessibility」で、そのストーリーの自動テストの結果が見られます。自動テストで見つからないもの（読み上げの順番、フォーカスの戻り先）は、キーボードとスクリーンリーダーで実際に操作して確かめます。
